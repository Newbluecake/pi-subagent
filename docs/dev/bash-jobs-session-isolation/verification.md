## 验收中另发现的**未自报**偏离/缺陷

1. **🟡-a（终审"实现期必须处理"）未实现**：`moveRecordFiles` 对日志 rename 的 ENOENT 静默**继续**（`session-dirs.ts:112-116`），未改为"放弃该条记录"，也无 `"wx"` 占位认领与认领前活性复查 → 两进程并发启动可**双收养**同一孤儿（双通知、双 kill 责任）。终审 🟡-a 明确要求二选一实现。
2. **`gcSessionDir` 不清理孤独 `session-id` 文件**（`session-dirs.ts:203-210`：仅 `left.length === 0` 才 rmdir）。而 `stack.ts:187-189` 给**每个** session 目录都写 `session-id` → 每个跑过 bash 的会话目录**永久残留**，违反 plan §2 不变量"目录数量 ≈ 近 retention 窗口内的会话数"与 §3.3"孤独 session-id 随 rmdir 清掉"。
3. **跨目录交接后内存记录 logPath 过期（真实小 bug）**：plan §3.5 要求"更新 handoff.record 为新路径版本后再 adopt"，实现直接把旧记录交给 `adoptLocalJobs`（`session-dirs.ts:174-183`）。`readOutput` 读内存 `record.logPath`（`manager.ts:701-708`），`fileSize` ENOENT 静默返 0（`:1026-1032`）→ new/fork 交接后、job 仍在跑期间，`bash_job status` 的 tail 为空、展示路径指向已搬走的旧位置；终态后 `applyTransition→putRecord` 才自愈。reload（同目录）不受影响。
4. `moveRecordFiles` 目标存在 WARN 只带单方 command，未带双方 createdAt/command 预览（🟢-6 部分落实）。

## 总体结论：**不通过**（修复项明确、范围可控）

核心实现（owner token、GC 同构、迁移顺序、通知收敛、drain barrier、权限）码检质量高，全量 1537 测试绿；但方案 v3.1 §5 把下列测试列为交付物与把关点，它们**整体缺失**，且存在 3 项未自报的代码偏离（含 1 个并发正确性缺口、1 个真实小 bug）。

**修复项**：

1. 补 🟡-I① fork 后 `exitCode===7` 集成把关测试（🔴-A 的唯一端到端验证）；
2. 补 manager 单测：export/adopt owner 转移、A→B→C 恰好落盘一次、前台 job 不导出、exit/export 交叠两窗口、deliverNotice 收敛；
3. 补 🟡-I② startup 孤儿收养、🟡-I③ adopted 后 fork 集成用例；补 job-store 的 root 外拒删 / dirMode / rename 重试用例；补 GC 的 `.DS_Store` 放行、`retentionMs<=0`、🟡-F root 终态出口用例；
4. 实现 🟡-a 排他认领（日志 rename ENOENT 即放弃该条，或 `"wx"` 占位）；
5. 修跨目录 handoff 的内存 logPath/sessionId 更新（adopt 前 patch handoff.record）；
6. `gcSessionDir` 清理孤独 `session-id` 后 rmdir；`reconcileRootDir` 接线 `skipDirNames: [selfDirName]`。
